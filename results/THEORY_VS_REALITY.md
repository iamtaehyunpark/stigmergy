## 2026-07-09 - Small model cannot do budget-allocation arithmetic single-shot

- Assumption or gap: The spec's budget rule (sum of child budgets <= B - k) assumes the model can perform the arithmetic while composing the action document.
- What actually happened: qwen3.6 at temperature 0 violated the sum constraint on 5/20 tasks even with worked examples in the prompt (harness_v2 single-shot: 15/20). Replacing free allocation with fixed patterns (v3: uniform; v4/v5: tiered with one deep slot) eliminated violations entirely, at the cost of removing the quantitative half of the allocation decision from the agent.
- Implication for `RATD_Theory.md`: Section 6's budget conservation is sound, but *allocation* is a capability assumption that small models fail. Either the runtime clips (spec 2.2 already allows this) or the harness supplies safe patterns; which subtask deserves depth remains a semantic judgment the model handles well. "Economic constraints on recursive spawning" deserves its own treatment.

## 2026-07-09 - Interface orphaning: recursion + namespace isolation + gating were jointly inconsistent

- Assumption or gap: The theory treats namespace isolation (section 4) and recursive decomposition (section 3) as independently sound; neither the spec nor the harness said who writes a child's parent-declared output path if that child spawns instead of executing.
- What actually happened: In harness_v4 runs, every deep run died the same way: a spawning agent writes no data itself, its children may not write outside their own namespaces, so the interface path the parent's triggers were gated on could never legally be produced (t15 both reps, t09_r2; the 5 missing schema agreements were exactly these paths).
- Implication for `RATD_Theory.md`: The iota capsule must carry an interface *contract*, not just context: parent-assigned output paths are delegable obligations, and inherited interface paths are the single principled exception to namespace discipline. Fixed in harness_v5 plus mechanical validator support; schema agreement returned to 100%.

## 2026-07-09 - DEFER was a silent drop: Delta-C semantics must cover all rule-authoring actions

- Assumption or gap: Theory section 1.3 defines the runtime as firing newly-true rules after every change, and section 1.2 says every agent step returns (Delta-D, Delta-C). The Phase 2 runtime implemented Delta-C for SPAWN conditions but DEFER only logged.
- What actually happened: A correctly-behaving agent (root.2.1 in t09, needing sibling-branch memory it could not see) deferred naming an already-done path and was silently dropped from the circuit; both t09 reps failed with root_outputs starved. Fixed by registering (wake_condition, same agent re-enqueued with condition = wake_condition): already-true wakes fire on the next trigger pass, and condition refs grant the woken agent visibility of exactly the memory it named. 6/6 convergence followed.
- Implication for `RATD_Theory.md`: Two lessons. (1) Every action that authors a rule is a Delta-C edit and must be installed in C - "fire newly-true rules" includes rules that are true at installation (the Petri-net analogue: adding an enabled transition must schedule it). (2) DEFER-then-wake doubles as the visibility mechanism for cross-branch dependencies: the wake condition is simultaneously a scheduling constraint and a read grant. That coupling was not in the theory and is worth stating.

## 2026-07-10 - E0-min: SPAWN is spawn-and-continue; the terminal-step model of section 1.2 is wrong

- Assumption or gap: Theory section 1.2 models an agent's step as terminal - emit (Delta-D, Delta-C) and exit; a spawning agent contributes only Delta-C. The E0 participation rule (spec 0.2) forces every spawner to also declare a self_role job it executes itself.
- What actually happened: 12/12 E0 runs converged with the rule in force; validation rejected-and-repaired SPAWNs lacking self_role without any convergence cost. The self_role was the gated integrator in 69/69 cases (0 parallel shares, 0 review jobs).
- Implication for `RATD_Theory.md`: Section 1.2 should model SPAWN as spawn-and-continue: the agent's step returns (Delta-D, Delta-C) where Delta-D may be deferred behind a trigger the agent registers for itself. Every agent contributes data, not just rules - there are no pure-router nodes. This is also the cleanest statement of why interface orphaning (probe finding) cannot recur: the interface owner stays alive until its interface is written.

## 2026-07-10 - Zero conflicts is partly an artifact of serialized execution; concurrency was never exercised (user observation from the visualizer)

- Assumption or gap: The zero-conflict record (68+ cumulative runs) has been read as evidence of coordination safety. But the runtime is strictly single-threaded: `while self.queue: agent = self.queue.pop(0)` (phase2.py run loop). "Parallel" siblings are only logically unordered - execution is one serial interleaving chosen by FIFO, and every agent's read -> LLM -> write cycle is atomic against all others. Every routing decision therefore saw a complete, fully up-to-date memory state for free. Spotted by the user while replaying runs in the visualizer.
- What actually happened (re-analysis, no new runs): the finding splits. SURVIVES parallelism: the validator confines each agent's writes to its own namespace or explicitly owed paths, so write-write conflicts on a path are structurally impossible under any schedule - that part is architecture, not luck. NEVER TESTED: (1) stale-read decisions - under true parallelism an agent's SPAWN/DEFER/EXECUTE choice is based on a snapshot that goes stale during its 30-60s LLM call (the L3_r1 blind-defer class gets strictly worse: one could defer on an address being written under a different name at that moment); (2) duplicate work - stigmergy coordinates through COMPLETED traces; there is no signal for in-flight work, so two parallel branches that both need a glossary will both build one; zero-duplication findings rode on full visibility; (3) trigger races - exactly-once firing is trivial when fire_ready_triggers() runs between steps in one thread; concurrent completions satisfying the same AND-condition need an atomic check-and-set on the fired flag; (4) all temp-0 determinism/clustering observations are conditioned on FIFO order and dissolve under racy completion order.
- Implication for `RATD_Theory.md` and the design spec: restate section 4's claim as "write conflicts impossible by construction; coordination races unexercised" - the trace is a record, not a reservation. For the memory/circuit design worksheet this adds two [CHOOSE] items and two requirements: [CHOOSE] snapshot semantics (what an agent sees: snapshot-at-dequeue, which serialization currently emulates, vs live state); [CHOOSE] in-flight reservation (a claimed/being-produced entry status between absent and done, so parallel branches can see intent - interacts with A5 entry structure, and a claimed-but-never-completed entry becomes a sixth mechanically detectable failure class for the doctor); REQUIRED: atomic exactly-once trigger firing (CAS on fired); REQUIRED: race-safe quiescence for the doctor trigger ("queue empty" no longer implies "nothing running"). Also strengthens A3 write-once: write-once + first-writer-wins makes the blackboard lock-free under concurrency, while mutable entries would force versioning or locking. Mitigating note: parent-planned interfaces (the dominant observed pattern) are themselves a concurrency defense - siblings consuming only declared owed paths never need in-flight state; the exposure is concentrated exactly in the emergent/organic coordination Figure-1 probed.

## 2026-07-20 - v2 build: where the spec under-determined the runtime, and what was decided

- Assumption or gap: Playground Spec v2 + ET spec fix the architecture but leave realization choices open. Each decision below is logged before the freeze; all are mechanical and arm-symmetric unless stated.
- What was decided:
  1. **Arm S delivery channel.** "One LLM call per activation" leaves open how read results reach the emitter. Resolved: ops in an emission execute after the call ends; their results are delivered verbatim (bounded) in the NEXT activation's prompt iff the agent chained (`continue`/`wait`). No transcript carries over — the next activation sees identity block + activation cause + previous ops' results only. This is the v1 LIST/FETCH-costs-a-call pattern re-hosted, and it makes every activation boundary a measurable delivery channel (ET §3's continuity-locus diagnostics).
  2. **Arm S terminality.** An emission ending with no terminal op is recorded `done` (logged `implicit_done`). `continue` (= add_rule(True → resume self)) is exposed to Arm S only — it is the single-shot model's activation-chaining necessity, implemented as an ordinary circuit rule so S's "rounds" are circuit-expressed and countable.
  3. **Planner surface.** ET spec excludes `spawn`+`circuit.*` for workers but is silent on the planner. Resolved: the planner gets `spawn` + `wait` but NOT `circuit.*` — a planner authoring spawn-rules would emulate Arm R's mechanism inside Arm P and contaminate the P-vs-R isolation. `wait` is kept (mechanical suspension; internally a resume-self rule) so the planner is not forced to burn rounds polling — that would be a cost-axis artifact, not a planning-locus effect.
  4. **"Unhandled failed agent"** in the failure predicate: v2.0 has no handling mechanism, so every agent in state `failed` at run end counts as unhandled. If agents spontaneously repair a failure (respawn a substitute), the failed state remains and the verdict still flags it — the trace shows the repair; the predicate stays mechanical.
  5. **Divergence flag** (spec: "concurrent-write ... divergence flagged"): under a serial runtime "concurrent" needs a mechanical proxy. Resolved: a commit over a head authored by a different agent, when the committer has never read ANY version of that artifact, flags DIVERGENT (a visible blind overwrite). Read-then-overwrite is ordinary versioning; blind overwrite is the observable hazard.
  6. **Tool surface deltas vs spec §4 (declared, not silent):** `workspace.write` gained `append?`, reads gained `offset?` — direct remedies for E1's assembly-output-cap failure (single-emission artifacts are token-bounded; large artifacts are built incrementally and read in bounded pages with visible markers). Same tools, same caps, all arms.
  7. **Deliverable convention:** every task instructs delivery under `global/final/` (multi-part allowed). A single `global.commit` payload is bounded by the per-call output cap, so book-sized single-file finals are impossible by construction — the E1 stub-artifact wall is designed out rather than patched around. Judge input = concatenated heads under `global/final/*`, path order, same rule for all arms.
  8. **Round emission syntax:** free text with fenced JSON tool blocks (several per round, executed in order; text outside blocks is logged private reasoning). No response_format constraint, no schema-as-action, no repair loop: malformed blocks come back as parse-error observations and the agent deals with them (stance 2). Terminal ops (`done`/`fail`/`wait`/`continue`) end the round; later blocks in the same emission are skipped and logged.
  9. **Rule-eval errors** are logged deduplicated (on message change) — a permanently malformed rule would otherwise write thousands of identical trace lines across sweeps; the armed-but-unevaluable state is still visible every sweep in `circuit.inspect`.
- Implication: none of these touch the causal variables (planning locus, continuity locus); all are frozen in the pre-registration and identical across arms wherever the arm's model allows.

  3. ## 2026-07-20 - v2 smoke round 3 (R/L3): paging economics, not coordination, was the binding constraint

- Assumption or gap: READ_CAP=6000 chars per bounded read was an arbitrary substrate parameter assumed generous enough; rounds were assumed to be spent on reasoning and coordination.
- What actually happened: root's L3 run was structurally CORRECT - planned, spawned 4 chapter agents, gated its waits over terminal states (round-2 guidance adopted verbatim), resumed exactly when the gate fired, and when the glossary agent died, root adaptively took the job over itself. But chapters landed at 20-33k chars each (the 8k-token emission cap permits ~30k-char commits), so consuming them at 6k/page cost ~16 rounds; the glossary agent spent ALL 30 of its rounds on global.read paging without writing a word, and root committed its glossary rescue on its literal last round, leaving assembly undone. Both terminations were paging deaths, not judgment failures. The model also never batched multiple page-reads into one round, though the substrate allows several tool calls per emission.
- Decision: READ_CAP 6000 -> 12000 (bounded-returns law intact - cap + visible marker + offset paging), and one core-guidance line that independent calls (successive pages, multiple artifacts) can be batched per round. Arm-symmetric substrate parameters, pre-freeze. Note for the paper: the ratio (emission cap / read cap) sets how many rounds a reader pays per artifact a writer emits in one round - an asymmetric channel-width parameter the theory's cost model does not currently name.

## 2026-07-20 - v2 smoke round 3 (P/L3): the delivery channel for large artifacts did not exist; commit-by-reference added

- Assumption or gap: workspace append + bounded reads solved the E1 assembly wall; global.commit(path, content, summary) was assumed sufficient for delivery.
- What actually happened: worker a2 assembled a correct 36k-char chapter in its workspace via appends - the round-2 fix worked - and then had NO legal way to deliver it: a single commit cannot exceed the emission cap (~30k chars at 8k tokens), so it committed four sections as four successive VERSIONS of global/final/chapter_2.md, and linear versioning left the head holding only the last section. Separately, worker a3 burned 22 of 30 rounds on emissions cut at the cap, ignoring the cut notice every time (temp-0 idiosyncrasy; a2/a4 adapted after one notice). The planner also cap-cut once during assembly. 3 of 4 workers + planner terminated at R_max; 2.78M tokens spent for two deliverable chapters.
- Decision: (1) global.commit accepts `from_workspace` - commit a workspace file's content by reference, no re-emission; assemble-in-workspace -> deliver-by-reference closes the E1 assembly wall structurally instead of patching around it. (2) Emission cap raised 8k -> 16k tokens and READ_CAP 12k -> 20k chars, keeping the (emission cap / read cap) channel ratio at <= ~3 pages per artifact; the cap remains, with visible cut notices, as the bounded-emission law - it just no longer sits inside the task's natural artifact size. All arm-symmetric, pre-freeze.
- Implication for the theory: "reads are grants" now has a dual - WRITES are emissions, and the emission cap is a channel-width parameter on the producer side. The substrate must provide a by-reference path from private assembly space to shared memory, or every architecture pays O(artifact/cap) redundant emission cost at delivery time.

## 2026-07-21 - v2 smoke round 5: the purest memory-is-the-machine failure yet - an agent with no externalized state is a deterministic fixed point

- Assumption or gap: implicit-continue (round-2 fix) assumed a chained agent makes progress because each activation receives its predecessor's op results.

Since it externalized nothing, each activation's context was genuinely identical to the one two steps before - at temp 0 it can never escape. The substrate thesis in negative: an S agent without workspace writes has NO memory at all, and my implicit-continue default supplied unbounded re-activation to an agent that had authored none. Root also duplicated chapter agents (a5-a7 duplicating a2-a4) after monitoring reads - first organic duplicate-work incident for the emergence inventory.
- Decision: implicit chaining now requires mechanical evidence of work - an emission with no terminal op auto-chains iff it changed state (write/commit/spawn/rule edit) or was cut at the output cap; a read-only no-terminal emission is recorded done (`implicit_done_readonly`): pure observation without externalization is a fixed point and cannot progress by re-activation. Explicit continue/wait chains remain unrestricted - conscious read chains are the agent's right. Harness S text states the rule. Also: run.py partial-dir clearing survives AFS busy-file locks (move-aside fallback) after a crash killed an entire arm sweep.
- Implication for the theory: "continuity lives in the substrate" has a sharp corollary the spec never states - substrate continuity is EARNED by externalization, not granted by re-activation. ## 2026-07-21 - v2 smoke round 6: zero-grace fixed-point rule killed orientation reads; one grace chain is the correct window

## 2026-07-21 - (user-identified, mid-ladder) context re-acquisition is unamortized at BOTH layers - the priced quantity, and the next design cycle

- Assumption or gap: the v2 cost model treats per-call context as the natural unit; nothing in the theory prices RE-acquisition of shared context across rounds, activations, and agents.

The traces support quantifying it post-hoc: repeated-read token volume per run, per-call prefill sizes.
- Next-cycle design space (deferred capability, unlock = post-ET): (1) iota-as-KV-prefix - spawn children with the parent's relevant KV instead of text they must re-read (Latent Handoff integration; theory 2.1's design fork revisited at the serving layer); (2) grow-then-compact windows - sliding windows shred prefix reusability, compaction keeps a stable cacheable prefix; (3) read-by-reference with server-side KV sharing of hot artifacts (EngramTrace thesis: memory structure determines computational cost); (4) an APC-capable serving path for architectures that support it. Each changes the coordination-cost constants the theory's O(1)-vs-O(n) argument is stated in - the argument's FORM survives, its constants do not.
